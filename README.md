# Serendipity — 酒馆插件（剧情记忆 + 时间轴 + 人物 + 一致性检查 + 伏笔 + 屏蔽词 + 指令）

SillyTavern 第三方扩展：自动剧情记忆总结、结构化剧情时间轴、人物档案 + 情感线/关系轨迹、剧情一致性检查、伏笔/未完成事项管理、剧情屏蔽词过滤、以及指令系统。入口挂在酒馆「扩展」菜单（wand 菜单）里，面板为实色白，整插件按角色卡绑定。

## 功能

### 记忆
- **模型底层记忆规则**：记忆功能开启时，会注入一套「剧情时间/事件/人物/世界状态连续性」底层规则给模型——剧情时间是绝对坐标（第 N 天就是第 N 天）、区分剧情时间与现实记录时间、时间只在剧情明确推进时才推进、相对时间换算成绝对时间、历史与当前状态区分、不因上下文滚动把过去误当「昨天」、不无依据篡改历史、同名角色不因姓名相同而合并身份（前世/今生/平行世界视为不同人）。让模型在长篇剧情里不串时间、不失忆。
- 每轮对话（AI 生成回复）结束后，自动调用当前模型做一次「安静总结」。
- 总结字段：时间（年/月/日 周几 几时几分）、天气、在场人物、地点、关键事件、角色与用户衣着、物品、约定/承诺、已完成约定、本段详细总结。
- 两档记忆，自动晋级：
  - **短期记忆**：每轮的详细总结，满 10 条后合并成一条写入 **长期记忆**，并清空短期。
  - **长期记忆**：满 10 条会**提醒你「注入世界书」归档并清空**（不再自动生成永久记忆），正文注入始终有界。
- **长期记忆可折叠**（默认收起），短期记忆置顶、默认展开，方便快速查看最近的剧情。
- 记忆**只叠加、不覆盖**：除你在面板里手动点「删除」，或归档世界书后清空长期记忆外，插件不会删除记忆。
- 每条记忆可点「**编辑**」就地修改内容并保存，保存后立即更新注入正文的记忆。
- **记忆重要度（S/A/B 分级）**：总结时让模型给每条记忆打级——S=绝对不能忘/重大转折、A=重要剧情、B=普通日常。S 级记忆注入正文时**排最前**并加「⚠ 绝对不能忘」标记、A 级次之，保证关键信息不被长对话淹没；记忆列表显示 S/A 徽标，编辑态可改重要度。
- **按角色挂靠（entityRef）**：每条记忆可关联到「人物档案」里的一个角色实体。总结写入新记忆时，若正文只出现一个已登记角色的名字就自动挂靠（多个名字/同名多个则留空，避免误挂）；记忆列表显示 👤角色 徽标，编辑态可用下拉改挂靠或取消；短期并长期时只有整批都挂同一个角色才带上关联；导出记忆带「[关于 角色名]」前缀。
- **剧情时间接力**：每次总结都会把「上一次剧情时间」传给模型，让它判断是否推进、保持一致；记忆按剧情时间排序并显示剧情时间（真实记录时间在鼠标悬停时可见）。避免上百轮后 AI 仍把早期情节当作「昨天」。
- 记忆会被**注入正文 prompt**，生成时模型会读取并延续之前的设定与情节，防止失忆、避免前后矛盾。
- 可手动点「立即总结」触发一次，也可点「导出」把**记忆、时间线、人物、世界状态**一起下载为 .txt 文件。
- **独立总结 API**：记忆页的「总结 API 设置」可填一个 OpenAI 兼容接口（地址 / Key / 模型名，带「测试」按钮）。设置后，自动总结、立即总结、一致性检查都走这个 API，不占用聊天正在用的默认 API 额度；没设置，或调用失败时，自动回退到酒馆当前的默认 API（并弹提示）。设置全局共用，Key 存在酒馆设置里。注意：浏览器直连，接口需允许跨域（CORS），不允许时「测试」会报错。
- **每 N 轮总结**：默认每轮都总结，可在面板设置「每 N 轮总结一次」（N≥1），短回复/快刷屏时省调用量；跨轮时会把「上次总结以来的所有新消息」一起总结，不会漏掉中间跳过的剧情。
- **手动补记**：想立刻记下某个设定/事件、不等自动总结时，直接在面板输入框手写一条补进短期记忆（自动沿用当前剧情时间）。
- **一键清空**：面板底部「清空本角色数据」可一键清空该角色的全部记忆/时间线/人物/世界状态/屏蔽词/指令（二次确认，不可撤销），重开这个角色即干净一套。
- 每次总结完成后会弹窗提示**成功/失败**；若触发晋级会同时提示「已满十轮自动放入长期记忆」；长期记忆满 10 条时会额外提醒你归档世界书。
- **归档到世界书**：长期记忆满 10 条后，在面板里用下拉框**自己选择要注入的世界书**（不一定要用角色绑定的那本），点「**注入世界书**」把长期记忆**每条单独写成一条带关键词的条目**（标题 `[Serendipity] <重要度><摘要>`，内容=**记忆原文** + 时间前缀）并**清空长期记忆**。写入格式：**不常驻**、**选择性触发**（靠关键词按需召回，不再每轮全量注入）、**关键词 = 正文里出现的人物实体名 + 关联实体 + 地点**（都没有时兜底用当前角色名）、**绑定角色 = 当前角色名**、**插入位置 = [系统]角色设定之前**。这样酒馆的关键词匹配会在剧情聊到相关人物/地点时**按需召回对应的记忆原文**，而不是把所有记忆每轮硬塞进 prompt。**注意**：写入后还要在酒馆「世界书」界面把这本世界书**激活**（设为全局世界书、或绑定到此角色），模型才会读到它；插件会在归档时弹窗提示，并在**归档后一直没激活时，在面板顶部给一条常驻黄条**提醒，直到你把那本世界书激活为止。已用旧版本归档过的 `[Serendipity] 剧情记忆归档` 常驻条目会原样保留（不再新增内容），想彻底切到按需召回可在世界书里手动删除它。
- **归档用向量召回（语义召回）**：打开面板里「归档用向量召回」开关后，归档条目会标记 `vectorized`，交给酒馆内置「**向量存储**」扩展按**语义**召回原文——即使当前对话没直接提到人物/地点名，也能靠意思相近把相关旧记忆找回来。**前提**：在酒馆「扩展 → 向量存储」里①启用「世界书向量化（World Info）」②选好并配好 embedding 源（OpenAI / Ollama / Google / 本地 WebLLM 等）。没配好就打开开关的话，这些条目会**既不走关键词也不走向量，召回不到**，所以默认关着、保持关键词召回。开启向量化后，关键词仍在但不再驱动召回（酒馆条目是三态：常驻/关键词/向量，向量态由语义匹配触发）。
- **「向量召回」页（面板内语义搜索）**：独立一个页签，输入一句话点「**语义搜索**」，插件直接调一次酒馆「向量存储」把**会被语义召回的记忆原文按相似度从高到低列出来**，让用户在面板里就能看到向量召回到底召回到了啥（不用开控制台）。页顶状态条会显示当前 embedding 源/模型、世界书向量化是否已启用；可下拉选择要查哪本世界书（默认归档的那本）；还带**预览调参**（阈值 / 条数，只影响这里预览、不改实际召回），没召回时把阈值调到 0 就能看向量库里到底有什么；每条结果带「**复制**」按钮可直接复制原文。前提同上一节：向量存储里开了世界书向量化、配好 embedding 源、那本世界书已激活并跑过至少一轮生成让向量库索引到这些条目；没命中会给出可能原因。
- **自动语义召回注入正文**：同一页上半部分「注入正文」开关（默认关）。开启后，插件把本角色当前的数据（短期/长期记忆、时间线、人物档案、关系、未回收伏笔、世界状态）写进酒馆向量库的**独立集合**，每轮生成结束后按当前对话语义召回、按（相似度排名 + 重要度 S/A + 时间远近 + 近期点名角色）加权排序、去重后取前几条，以「[Serendipity 语义召回]」注入下一轮正文，让模型在长对话里自然接住过往剧情、不靠用户手动翻。可调召回条数 / 候选阈值 / 候选条数；换 embedding 源或模型会自动全量重建索引；带「重建索引」按钮 + 索引条数状态。**前提**同向量召回：酒馆「向量存储」已启用并配好 embedding 源（WebLLM 本地源不支持）。

### 时间轴
- 每次总结输出一行结构化**时间轴**：`第X天 | 地点 | 重要事情`，插件把【时间】里的具体时间（年月日几时几分）一起拼成**时间线列表**逐条叠加（不断累积、不覆盖）：`第X天 / 年月日几时几分 / 地点 / 重要事情`。
- **已过 X 天**：面板「时间轴」页顶部显示当前锚点「**已过 X 天 · 年月日几时几分 · 地点**」，一眼看出剧情总共过了几天。
- **第X天接力推进**：总结时把上一次的「第X天 + 年月日几时几分 + 地点」传给模型，模型只在剧情明确推进天数时才改天数，否则沿用，时间轴不会每轮乱跳。
- 面板「时间轴」页显示**当前锚点**和下方**时间线列表**（第X天 / 年月日几时几分 / 地点 / 重要事情），可手动设定锚点，也可对每条时间线**编辑 / 删除**。
- **相对时间校验**：自动抓最新回复里的「昨天/前天/上周…」，换算成第X天并提示核对，专治「AI 把三天前说成昨天」。

### 人物（档案 + 关系 + 物品·日程）
「世界」与「情感线」两部分已融合成同一个「**人物**」页，分三块：

- **人物档案（角色实体）**：列表登记**姓名 / 年龄 / 简介 + 身份域（世界 · 时间线 · 身份）**——这是「人物登记册」，只记这个人是谁；身份域用来区分同名角色（前世「沈昭·将军」与今生「沈昭·医生」是两个独立实体）。**好感与关系不在这里**，统一放到下方「关系」里按配对维护，两者不重复。总结会自动登记在场人物并带出年龄/简介/身份域；遇到拿不准的同名情况会在列表里弹一条**待确认**卡片，让你选「归到候选 / 新建独立 / 忽略」。
- **人物状态**：每个角色实体另有「身体 / 心理 / 目标 / 秘密 / 承诺」五个结构化字段，随总结的【人物档案】行自动带出；「目标/秘密/承诺」注入正文让 AI 每次牢记，「身体/心理」只在面板显示（不占每轮 token）。人物档案列表在角色名下显示**状态标签**（身体：… / 心理：… / 目标：… / 秘密：… / 承诺：…），编辑态展开 10 个字段（姓名/身份域/年龄/简介 + 五个状态）逐个改。
- **关系 / 好感（情感线）**：回答「**现在是什么关系**」+「**怎么变成现在这样**」。
  - 每次总结额外解析一行**关系变化**：模型只有在剧情中**确实发生了明确的关系/好感/态度/情绪变化**时才输出（写「无」就不记录，不会因为普通对话硬编「感情更加深厚」）。
  - **历史只追加、不覆盖**：关系可以变好，也可以恶化、疏远、决裂、恢复；过去的关系阶段不会被后续总结改写，当前关系是历史累积后的结果。
  - 数据按「**谁 → 谁**」成对独立：`A → B 恋人`、`A → C 朋友`、`A → D 敌对` 各是一条线，互不干扰；方向敏感（A 对 B 与 B 对 A 是两条线）。
  - 每条线一张卡片，展示当前关系 + 历史轨迹（第X天 → 变化 + 原因 + 事件），可手动建立/补记/删除；关系轨迹会**注入正文**（当前关系始终注入 + 最近 5 条变化 + 关键节点，token 有界）。
- **物品 · 日程**：世界状态现在只放非人物信息，覆盖 **物品 / 日程** 两类。
  - **快照式更新**：某类别本次总结有新内容就替换整类；写「无」则保留原样；写「空」则清空该类，列表始终保持当前最新状态，不会越滚越乱。
  - 按类别分组展示，可**手动添加 / 编辑 / 删除**，条目即时生效，并**注入正文 prompt** 供模型每轮遵守。
- **一次性迁移**：旧版世界状态里的「年龄」会自动转成角色实体档案，「好感/关系」扁平条目交由关系线体系承接（需在「人物→关系」里按配对重建），不会重复。

### 屏蔽词
- 输入屏蔽词（如「极其」）后立即把剧情与状态栏里所有该词眼**直接删除**。
- 屏蔽词同时被**注入正文 prompt**，明确要求模型不得再输出这些词，从根本上防止该词反复出现。
- 界面显示层删除不会改动聊天数据，关闭屏蔽后刷新页面可恢复原文。

### 指令
- 指令**数量不限**，可随时添加、删除；每条指令自带独立开关，可单独开启/关闭。
- 已开启的指令每轮生成都会注入正文 prompt，模型每轮都会读取并遵守。

### 剧情一致性检查
- 面板新增「检查」页，一键让模型对照「当前时间轴 + 已有时间线/世界状态/记忆」排查矛盾，例如：
  - ⚠ **时间冲突**：记忆里第 12 天发生的事，当前剧情才进行到第 10 天；
  - ⚠ **状态冲突**：某人第 8 天已离开京城，第 10 天却仍在京城。
- **只在点「立即检查」时调用一次模型**；每次总结后还会**免费跑一次本地时间冲突启发式**（对照时间线/记忆的「第X天」与当前天数）。
- **验证层闭环**：已发现的冲突默认**注入每轮正文**（「[Serendipity 一致性提醒] 请在后续生成中保持一致、避免再犯同样的错」，最多带最近 5 条，措辞强调不改写历史、只避免今后自相矛盾），让模型在生成时就能避开已知矛盾；可在「检查」页关掉该注入。
- 冲突按「时间冲突 / 状态冲突 / 其他」分类标色列出，可单条忽略、一键清空；有冲突时「检查」页签会显示数量角标。

### 伏笔 / 未完成事项
- 面板新增「伏笔」页，把还没揭晓的悬念、未完成的承诺/待办记下来（如「沈砚身上的旧伤」「密信的真正来源」），本地管理。
- 每条伏笔有状态标签（**未揭示 / 未解决 / 进行中 / 已回收**），点一下循环切换；可编辑标题与备注、可删除。
- 未完成的伏笔会在「伏笔」页签显示数量角标提醒；默认**不注入正文**，开启页内开关后会把未完成伏笔紧凑注入正文，提醒模型别遗忘、别提前说破。

### 角色卡绑定
- 整插件（记忆、屏蔽词、指令）**按角色卡绑定**（以角色卡唯一标识 avatar 为准，同名卡也各自独立）：换到新角色卡时插件是干净的一套，切回旧角色卡则恢复该角色卡自己的记忆/屏蔽词/指令，互不串扰。
- **同一角色卡的不同聊天也各自独立**：数据按「角色 + 聊天」双维度隔离存储，开启新对话就是全新的一套记忆/时间轴/世界状态，**不再把上一个聊天页面的内容带进新对话**；切回旧聊天则恢复那个聊天自己的记录。想手动彻底重开当前聊天，可用面板底部的「清空本角色数据」。

## 语义召回（向量召回）· 启用与验证

把长期记忆归档到世界书后，除了关键词召回，还能用酒馆内置「向量存储」按**语义**找回相关旧记忆——即使当前对话没直接提到人物/地点名，也能靠意思相近把历史原文带回来。

**前提**：酒馆需启用「向量存储」扩展（自带），并配好一个 embedding 源。

### 启用步骤

1. **配 embedding 源**（扩展 → 向量存储 → Vectorization Source）：
   - 通用：选一个源（OpenAI / Ollama / SiliconFlow / Google …），按提示填好 key / 地址 / 模型。
   - **重要**：如果你的聊天网关是 OpenAI 兼容中转（New API / one-api 等），酒馆的「OpenAI」向量源是**写死 `api.openai.com`**、不读自定义 Base URL 的。此时请用 **「vLLM」源当「通用 OpenAI 兼容接口」**来填：到「API 连接 → 文本补全 → vLLM」填**服务器地址 = 你的网关域名**、**API key = 你的 key**（只给向量存储用，聊天 API 不用切到 vLLM），再回向量存储把源选 vLLM、模型填你网关的 embedding 模型（如 `bge-m3` / `text-embedding-3-small` / `qwen3-embedding-8b`）。「次级向量化端点 URL」留空即可。
2. **打开世界书向量化**：向量存储 → World Info settings → 勾上 **「Enable for World Info」**（总开关）。
3. **回 Serendipity**：打开「归档用向量召回」开关 → 重新点「注入世界书」→ 确认这本世界书已**激活**（全局世界书、或绑定到角色）。

### 验证召回有没有生效

- **控制台**（`F12` → Console → 过滤 `Vectors`）发一条消息看：
  - `Found N new WI entries` → embedding 建成了（源/key/模型全通）；
  - `Activated N WI entries` → 语义检索命中并注入，**召回成功**。
- **看提示词**：左侧栏「魔法棒」打开提示词，搜记忆里的某个词，看带「`第X天 · 时间：`」前缀的记忆原文有没有被带回。
- **行为测试**：发一句故意不提关键词、但语义相关的话（例：第 37 天收到玉佩 → 第 186 天说「我摸到了衣襟里那块冰凉的东西」），看 AI 会不会自己接上旧剧情。

### 调参

- 只 `Found` 不 `Activated`：把向量存储里的 `score_threshold` 调低（默认 0.25 → 0.15 左右）再试。
- 召回太松 / 混进无关的：调高 `score_threshold`，或把 `max_entries`（默认 5）调小。

## 架构

### 数据存储

整插件数据存于酒馆设置 `extension_settings.serendipity`，结构是一层分桶：

```
serendipity
└─ chars: { "<charKey>::<chatId>": 角色数据, ... }
```

- `<charKey>` = `avatar::<角色卡唯一头像>`（无头像退回 `name::<角色名>`），区分同名不同图的两张卡。
- `<chatId>` = `chat::<当前聊天文件名>`（取不到退回聊天文件头的 `integrity` UUID），区分同一角色卡的不同聊天。
- 键拼成「**角色 + 聊天**」双维度：换角色 / 换聊天各用各的一套，互不串扰；旧版按角色存的数据首次打开有历史的聊天时自动迁到对应聊天名下。

每个角色数据对象（`freshCharSettings`）的字段：

| 字段 | 含义 |
| --- | --- |
| `memories` | 短期记忆，每条 `{ id, time, storyTime, storyDay, storyLocation, importance, entityRef, text }` |
| `longMemories` | 长期记忆（短期满 10 条合并而来），结构同上（含 `importance`/`entityRef`） |
| `memoryEnabled` / `summarizeEvery` / `roundsSinceSummary` / `lastSummaryIndex` | 记忆开关、每 N 轮总结、轮数计数、总结水位线 |
| `storyTime` / `storyDay` / `storyPeriod` / `storyLocation` | 当前剧情时间锚点（年月日几时几分 / 第X天 / 时段 / 地点） |
| `timeline` | 时间线叠加列表 `{ id, day, time, location, event }` |
| `worldState` | 世界状态列表 `{ id, cat, text }`（物品/日程） |
| `entities` | 角色实体列表 `{ id, name, age, note, world, timeline, identity, body, mind, goal, secret, promise }`（姓名/年龄/简介 + 身份域：世界/时间线/身份 + 人物状态：身体/心理/目标/秘密/承诺） |
| `relationshipLines` | 情感线列表 `{ id, a, b, current:{affection,relationship,attitude}, history:[{id,day,from,to,change,reason,event}] }`（谁→谁 + 当前关系 + 变化轨迹） |
| `blockedWords` / `censorEnabled` | 屏蔽词列表 / 开关 |
| `instructions` | 指令列表 `{ id, text, enabled }` |
| `foreshadows` / `injectForeshadows` | 伏笔列表 `{ id, title, status, note, day }` / 是否注入正文 |
| `checks` | 一致性检查结果 `{ id, type, text, day }` |
| `worldBook` / `archivedWorldBook` / `worldReminderShown` | 归档目标世界书 / 上次归档 / 归档提醒 |

### 记忆总结流水线（核心）

每一轮 AI 回复结束后（`GENERATION_ENDED`），按 `summarizeEvery`（每 N 轮）触发一次 `summarizeLastRound()`：

1. **取增量窗口**：用 `lastSummaryIndex` 水位线，只取「上次总结以来」的新消息（中间跳过的几轮一并带上，不漏剧情）；水位线越界（消息被删/回滚）时退化为最近一轮。
2. **构造总结 Prompt**（`buildSummaryPrompt`）：把上一次剧情时间、时间轴锚点、当前世界状态回传给模型，让它「接力推进」而不是每轮从零猜。
3. **调用模型**（`generateRaw`），返回总结按 `【…】` 标签逐行解析：
   - 【时间】 → 更新 `storyTime`（剧情时间锚点）
   - 【时间轴】「第X天|地点|重要事情」 → 更新 `storyDay`/`storyPeriod`/`storyLocation`，并 `pushTimelineEntry` 叠加进时间线
   - 【世界状态】「类别：内容；…」 → `applyWorldState` 快照式更新（「无」保留、「空」清空、有新内容替换整类）
   - 【关系变化】「A→B|变化|变化前|变化后|好感变化|当前态度|原因|事件|第X天」 → `applyRelationshipChange` 追加进情感线（无变化/解析失败则不动；历史只追加不改写）
   - 【人物档案】「姓名|年龄|简介|世界|时间线|身份|身体|心理|目标|秘密|承诺」 → `mergeEntityInfos` 自动登记/补全角色实体（同名按身份域归属，拿不准弹待确认）
   - 【重要度】S/A/B → 记入记忆的 `importance`
   - 其余正文（天气/在场人物/地点/关键事件/衣着/物品/约定承诺/详细总结…） → 存入短期记忆 `memories`（只追加、不覆盖），并按正文出现的唯一角色名推断 `entityRef` 挂靠
4. **晋级**：`memories` 满 10 条 → `promoteMemories` 合并成 1 条写入 `longMemories`，清空短期；`longMemories` 满 10 条提醒「注入世界书」归档。
5. **一致性**：总结后跑一次免费的本地时间冲突启发式（`refreshLocalChecks`）。

### 记忆分级与归档

- **短期记忆**：每轮的详细总结，置顶、默认展开，满 10 条晋级。
- **长期记忆**：短期合并而来，可折叠，满 10 条提醒归档到世界书（`injectToWorldBook` 把每条长期记忆单独写成一条带关键词（人物实体名 + 地点）的世界书条目，`constant=false`/`selective=true`，按关键词按需召回原文；开了「归档用向量召回」则标记 `vectorized=true` 交给酒馆向量存储做语义召回，归档后清空长期，正文注入始终有界）。
- 记忆**只叠加、不覆盖**：除手动删除、或归档后清空长期外，插件不删记忆。

### 正文注入（`updatePromptInjection`）

模型每轮生成前，插件用 `setExtensionPrompt` 注入以下块：

| 注入块 | 类型 | 内容 | 条件 |
| --- | --- | --- | --- |
| `serendipity_memory_rules` | IN_PROMPT | 记忆底层规则（剧情时间连续性等，只给模型看） | 记忆开关开 |
| `serendipity_memory` | IN_PROMPT | 长期 + 短期记忆（S 级置顶加「⚠ 绝对不能忘」标记） | 记忆开关开且有记忆 |
| `serendipity_time` | IN_PROMPT | 当前剧情时间锚点（第X天·时间·地点） | 有锚点 |
| `serendipity_world` | IN_PROMPT | 世界状态列表（物品/日程） | 有世界状态 |
| `serendipity_npcs` | IN_PROMPT | 角色实体档案（姓名/身份域/年龄/简介 + 目标/秘密/承诺） | 有角色实体 |
| `serendipity_relationship` | IN_PROMPT | 情感线（当前关系 + 最近 5 条变化 + 关键节点） | 有情感线 |
| `serendipity_foreshadow` | IN_PROMPT | 未完成伏笔提醒 | 伏笔注入开关开 |
| `serendipity_checks` | IN_PROMPT | 已发现的一致性冲突（避免再犯，最多 5 条） | 检查注入开关开（默认开） |
| `serendipity_censor` | BEFORE_PROMPT | 禁止词（绝不得出现） | 屏蔽开启且有词 |
| `serendipity_instructions` | BEFORE_PROMPT | 用户指令（最高优先级） | 有开启的指令 |

### 剧情一致性检查

- **本地启发式（免费、不调模型）**：对照时间线/记忆里的「第X天」与当前天数，出现倒退/超前即标 ⚠（每次总结后自动跑）。
- **模型深查（手动）**：「检查」页点「立即检查」，调一次模型对照时间轴/时间线/世界状态/记忆排查时间冲突与状态冲突。

### 伏笔 / 未完成事项

纯本地列表 + 状态机（未揭示/未解决/进行中/已回收），可选注入正文提醒模型别遗忘、别提前说破。

### 概念结构（剧情时间锚点）

```
                剧情时间锚点
                     │
                     ↓
              第 1 天 → 第 2 天 → 第 3 天
                     ↓
              第 20 天 → 第 50 天
                     ↓
                    第 87 天（当前）
                     │
          ┌──────────┼──────────┐
          ↓          ↓          ↓
        记忆       世界状态     时间线
          │          │          │
          └──────────┼──────────┘
                     ↓
                  当前剧情
```

- **剧情时间锚点**（`storyDay` 第X天 + `storyTime` 年月日几时几分 + `storyLocation` 地点）是唯一主轴，只在剧情明确推进时间时才向前走，不会因为多聊了几轮就擅自跳天。
- 每一天的总结同时沉淀成三样东西：**记忆**（短期→长期）、**世界状态**（当前快照）、**时间线**（叠加列表），三者都挂在「那一天」的时间坐标下。
- 三样东西**每轮都注入正文**，模型据此理解「现在进行到第几天、发生过什么、世界处于什么状态」，维持时间/事件/人物/世界状态的连续性——即「当前剧情」。

### 屏蔽词 / 指令

- **屏蔽词**：界面层直接删除文本（MutationObserver 实时监控）+ 注入正文禁止模型再输出。
- **指令**：无数量限制，逐条开关，注入正文最高优先级。

## 说明

- 记忆总结每次会额外调用一次模型，消耗少量额度（这是「自动总结」的正常开销）。
- 记忆存于酒馆设置（浏览器本地存储），长期大量累积可能接近存储上限。
- 本扩展 `auto_update` 已开启：酒馆检测到新版本并更新后，会自动刷新页面应用新版本（无需手动刷新）。
